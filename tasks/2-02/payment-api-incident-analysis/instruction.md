# 支付服务 Kubernetes 故障归因与恢复计划

你是支付平台运维工程师，收到一次服务异常的诊断资料，需要形成可供事故响应团队执行的恢复计划。

1. 阅读事故材料，关联配置、事件和日志中的证据
2. 定位多个根因及受影响资源
3. 提出参数明确的整改动作、回滚版本和恢复验证步骤

## 工作空间

输入材料位于 `/app/input/`，工具与接口位于 `/app/software/`。成果保存到 `/app/output/`。

## 交付文件

- `/app/output/root_cause_analysis.json`：根因、资源、原文证据、优先级整改、回滚及诊断摘要。

## 运行约定

保留输入材料，以交付文件或服务状态提交结果。根据任务说明使用提供的离线数据与工具。

## 具体工作要求

基于三份静态事故证据，分析支付API发布后的故障。不得连接真实集群。区分根因、症状与无关告警；为每个根因引用文件名及逐字原文，给出优先级、受影响资源、结构化整改参数与可回滚恢复顺序。中文说明不改变证据原文。输出合同见 schema.json。

## 运行与提交

输入目录 `/app/input`，工具目录 `/app/software`，工作目录 `/app`。仅向 `/app/output` 写入最终产物。可用 Python 科学计算环境；无需外网或私有账号。输入保持不变，所有报告正文使用中文，技术字段、ID 和枚举保持约定值。

## 交付要求

`root_cause_analysis.json`，含 roots、affected_resources、remediation、rollback、summary。
